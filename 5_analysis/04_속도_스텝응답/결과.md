# 속도 스텝응답

**목적** — rSP ↔ 실제 개폐 속도 커브
**수행** — 2026-07-15, 무부하 rPR 0↔255 왕복, rSP 5단계 × 3왕복(단계별 6회)

## 결과 (레이저 실측 기준)

| rSP | 제어 프로그램 측정 [s] | 레이저 실이동 [s] | 오버헤드 [s] | 제어 프로그램 기준 [mm/s] | 실제 속도 [mm/s] |
|---|---|---|---|---|---|
| 32 | 1.826 ± 0.099 | 1.440 | 0.386 | 29.2 | **37.0** |
| 64 | 1.306 ± 0.008 | 0.894 * | 0.412 * | 40.8 | **59.6 \*** |
| 128 | 1.057 ± 0.011 | 0.620 | 0.437 | 50.4 | **85.9** |
| 192 | 0.818 ± 0.006 | 0.450 | 0.368 | 65.1 | **118.3** |
| 255 | 0.816 ± 0.004 | 0.360 | 0.456 | 65.2 | **147.9** |

\* rSP=64 는 무부하 대조군에 해당 단계가 없어 오버헤드 평균(0.412 s)으로 추정한 값이다.
나머지 4단계는 레이저 직접 측정값이다. 속도는 전행정 53.24 mm 를 이동시간으로 나눈 것이다.

## 두 값이 다른 이유

`run.py` 가 재는 `move_time` 은 손가락 이동시간이 아니라 지령~응답 왕복 시간이다.

```python
t0 = time.perf_counter()
gr.move(target, rsp, 128)                # SET POS/SPE/FOR/GTO=1  (소켓 1왕복)
obj = gr.wait_arrival(..., poll=0.005)   # wait_latch(gPR 에코) 후 gOBJ != 0 폴링
dt = time.perf_counter() - t0
```

폴링 로그(333 Hz)로 이 구간을 쪼개면 이렇게 나온다.

| rSP | ① 지령→gPO 첫 변화 | ② gPO 변화 구간 | ③ 마지막 변화→gOBJ | gPO 갱신 | 총 | 레이저 실이동 |
|---|---|---|---|---|---|---|
| 32 | 364 ms | 1.466 s | 0 ms | 7회 | 1.826 s | 1.440 s |
| 64 | 322 ms | 0.979 s | 0 ms | 5회 | 1.306 s | — |
| 128 | 318 ms | 0.737 s | 0 ms | 4회 | 1.057 s | 0.620 s |
| 192 | 324 ms | 0.491 s | 0 ms | 3회 | 0.818 s | 0.450 s |
| 255 | 322 ms | 0.492 s | 0 ms | 3회 | 0.816 s | 0.360 s |

①은 rSP 와 무관하게 320 ms 안팎으로 일정하다. 소켓 왕복, 펌웨어 명령 접수와 모터 기동,
gPO 레지스터의 첫 갱신 대기가 여기 들어간다. ③은 0 ms 로, 이동이 끝나면 gOBJ 는 같은 폴링
주기에 바로 전환된다(무부하 대조군 결과와 일치).

②가 레이저보다 0.12 s 남짓 긴 것은 **gPO 가 전행정 중 3~7회만 갱신되기 때문**이다.
rSP 192 와 255 는 갱신이 3회뿐이라 관측 구간이 0.491 s / 0.492 s 로 뭉개진다. 레이저는
100 Hz 로 손가락을 직접 보므로 0.450 s / 0.360 s 로 구분된다.

오버헤드(① + 갱신 지연)는 rSP 와 무관하게 0.37~0.46 s(평균 0.41 s)로 일정하다. 이동시간이
짧을수록 전체에서 차지하는 비중이 커지므로 고속 구간일수록 속도가 압축되어 보인다.

## 그래프의 '겉보기 포화'

붉은선(제어 프로그램 측정)이 rSP 192~255 에서 평평해지지만, **그리퍼의 한계가 아니라 측정
경로의 한계다.** 그 구간의 실제 이동시간은 0.450 s → 0.360 s 로 0.09 s 줄어드는데, 고정
오버헤드 0.41 s 와 3회뿐인 gPO 갱신에 묻혀 총시간이 0.818 s / 0.816 s 로 같아진다.
같은 구간에서 녹색선(레이저)은 118 → 148 mm/s 로 계속 올라간다. **속도 지표는 녹색선을 쓴다.**

## rSP 와 실제 속도는 선형이다

- 평균 속도 = **21.6 + 0.499 × rSP** (R² = 0.9997)
- 최대 속도 = 24.3 + 0.529 × rSP (R² = 0.9981) — rSP 32/128/192/255 에서 41.8 / 92.6 / 122.8 / 161.3 mm/s

이 직선은 Robotiq 사양식(20~150 mm/s 를 rSP 0~255 에 선형 매핑)과 거의 같다.

| rSP | 레이저 실측 [mm/s] | 사양식 20+0.51·rSP | 편차 |
|---|---|---|---|
| 32 | 37.0 | 36.3 | +0.7 (+1.9%) |
| 128 | 85.9 | 85.3 | +0.6 (+0.8%) |
| 192 | 118.3 | 117.9 | +0.4 (+0.4%) |
| 255 | 147.9 | 150.0 | −2.1 (−1.4%) |

속도 거동은 사양서 그대로이고 포화는 없다. 실측 최대 147.9 mm/s 는 공칭 상한 150 mm/s 와
거의 일치하고, 최저 rSP=32 에서도 37.0 mm/s 로 공칭 하한 20 mm/s 보다 빠르다. 시뮬은 rSP 를
20~150 mm/s 로 선형 매핑하면 충분하다.

> **rSP=64 는 미확정이다.** 레이저 실측값이 없어 오버헤드 차감으로 추정한 59.6 mm/s 는
> 위 선형식의 53.5 mm/s · 사양식 52.6 mm/s 와 11% 차이가 난다. 그래프에는 빈 점으로
> 표시했으며, 확정하려면 rSP=64 를 포함해 측정장비와 함께 다시 측정해야 한다.

## 시뮬 반영

- 램프 속도 생성기는 위 표의 **실제 속도** 열을 쓴다(rSP 에 대해 단조 증가, 포화 없음)
- 실물과 시간축을 맞출 때는 제어 경로 오버헤드 0.41 s 를 별도 지연으로 둔다
- rSP=32 는 표준편차가 0.099 s 로 다른 단계(0.004~0.011 s)보다 10배 크다 — 저속 기동 마찰
